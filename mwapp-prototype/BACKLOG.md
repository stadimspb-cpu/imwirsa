# MWApp — Backlog отложенных идей

Этот файл — единственное надёжное место, где мы храним идеи, которые
хороши, но пока не сделаны. Не полагаемся на память Клода между чатами —
она суммирует прошлые разговоры фоново и может отставать или упускать
детали. Этот файл — наоборот, точный и постоянный.

**Как этим пользоваться:**
- Когда что-то откладываем — Клод добавляет сюда пункт, ты получаешь
  обновлённый файл вместе с остальными в тот же раз.
- Когда хочешь пересмотреть отложенное — просто загрузи этот файл в чат
  и скажи «глянь бэклог» или похожее. Клод прочитает и обсудит с тобой.
- Когда что-то из списка сделано — вычёркиваем/удаляем при следующей
  правке этого файла.
- Файл живёт в GitHub вместе с остальным кодом — значит, не потеряется,
  и его видно в истории коммитов.

## Отложено

### 1. Компактная шапка диалога с ассистентом после начала переписки
**Статус:** идея, не реализовано.
**Что это:** шапка (фото ассистента + кнопки) сейчас sticky и всегда
одной высоты (190px). Идея — при открытии показывать её как сейчас, а
как только пошли первые сообщения — плавно уменьшать (примерно вдвое),
не убирая совсем, чтобы освободить место под переписку в длинных диалогах.
**Почему отложено:** требует JS-логики отслеживания состояния «диалог
начался» + отдельного компактного CSS-варианта + плавного перехода
высоты — самостоятельная задача, не helper-фикс.
**Риск, если не делать:** нет — чисто эстетическое улучшение, не критично.

### 2. Настоящий эффект «контент просвечивает под Tab bar»
**Статус:** идея, частично реализовано другим способом.
**Что это:** сейчас Tab bar — отдельная полоса под экраном (не поверх
контента), с видимым тёмным градиентом. Андрей изначально хотел, чтобы
сам контент экрана визуально уходил и проглядывал сквозь полупрозрачную
панель при скролле — сигнал «внизу есть что-то ещё».
**Почему отложено:** требует превращения Tab bar в реальный оверлей
(position:absolute поверх экрана) + добавления нижних отступов на ВСЕХ
экранах (Home, Settings, Detail, Ship, Chat), чтобы контент не прятался
под непрозрачной нижней частью панели. Затрагивает много экранов сразу —
рискованно без живой проверки после каждого шага.
**Риск, если не делать:** нет — текущий вариант с градиентом уже
функционален и был протестирован, просто не даёт буквального
«просвечивания».

### 3. Голосовой ввод в диалоге с ассистентом
**Статус:** идея, признана нужной — делать точно, но не сейчас.
**Что это:** кнопка микрофона в поле ввода чата — моряк надиктовывает
сообщение вместо набора текста. Актуально на палубе, в перчатках, на
холоде, когда печатать неудобно.
**Как это делается технически:** браузерный Web Speech API
(`SpeechRecognition`) — распознавание речи прямо в браузере, без
сервера и доп. инфраструктуры.
**Что нужно проверить перед реализацией:**
- Стабильность именно в Safari на iPhone (тестовое устройство Андрея) —
  исторически менее надёжно, чем Chrome/Android.
- Точность распознавания в шумных условиях (двигатель, ветер, лебёдки
  на палубе) — в реальных условиях хуже, чем в тихом помещении.
- Переключение языка распознавания под 4 языка интерфейса — браузер не
  угадывает язык речи сам, нужно явно задавать.
**Почему отложено:** не критично для MVP/демо-этапа; требует
тестирования на реальном устройстве в реальных условиях, а не просто
кода.
**Риск, если не делать:** нет — это доп. удобство, а не замена текста;
без него текстовый ввод продолжает работать как есть.
